# Photo reconstruction options

Research note, 2026-11-01. This records the proposal before implementation; [automatic photo fitting](PHOTO_REFERENCE_FITTING.md) records the later implementation, including the user requirement to avoid manual coordinate setup. Recommendation only; no new model calls, downloads, experiments or product changes were made.

Prefer **one perception pass followed by bounded template fitting against the source image**. Keep an agent available for ambiguous object identities and support relations. This is an architectural recommendation, not a measured improvement over the current provider or a claim that another model would solve the photographed scene.

## What the repository establishes

`src/scene/deskScene.ts` uses an orthographic presentation camera. `imageRegion` is displayed by `PreviewPhotoReference.tsx`; it does not constrain placement. `photoPlacement.ts` performs bounded geometric repair and explicitly preserves scale, rotation and supports. Collision and contact validators therefore test scene validity, not agreement with the photograph. Many collision-free scenes can put the monitor, keyboard or stand in the wrong relative positions. The historical live observations in [PHOTO_EVALUATION.md](PHOTO_EVALUATION.md) and local acceptance cases in [PHOTO_PLACEMENT_REPAIR.md](PHOTO_PLACEMENT_REPAIR.md) are separate evidence; neither is a comparative reconstruction benchmark.

## Small practical design

1. **Infer image evidence and relations.** Ask the existing VLM for template identity, 2D region, visible contact point when identifiable, support candidates, occlusion order and uncertainty. Retain XYZ only as initialization. Distinguish a visible region from an inferred full-object extent.
2. **Fit a separate source camera and tabletop.** Propose tabletop corners automatically. Use a rectangular-desk aspect prior or user-reported dimensions, plus explicit camera assumptions. A plane homography helps locate points on that plane; elevated objects need contact anchors and template/camera fitting. Bounding-box centers must not be projected onto the desk as if they were contact points. If the desk is cropped or obscured, expose the uncertain plane for correction instead of silently treating it as calibrated. Actual dimensions remain optional for relative layout; inferred dimensions are not verified measurements.
3. **Fit existing templates with few variables.** Derive height from the support graph and contact profiles. Search bounded X/Z changes, modest size changes and a small set of yaw candidates, using projected anchors, outlines and regions. Account for occlusion when comparing visible regions: hidden template pixels must not be penalized as missing observations. Start with boxes and anchors; add segmentation only if that evidence is insufficient. Raw RGB similarity is a poor primary target across photographs and stylized voxel renders. These choices are proposed engineering judgments.
4. **Keep validity and fidelity separate.** Require the existing independent collision/contact check before apply, and also score source-view alignment. If satisfying geometry requires moving an item far from its image evidence, leave an explicit ambiguity for review. Preserve the orthographic hero view for presentation; the estimated photo camera serves fitting and visual comparison.
5. **Use agent steps selectively.** A bounded semantic retry can reconsider a disputed template or support relation. Numerical optimization belongs in the deterministic fitter. An LLM repair loop that sees only collision errors still lacks a photographic objective; adding iterations alone does not repair that omission.

The first implementation increment would be source-camera/plane estimation plus projected box/contact-anchor fitting, retaining the existing templates and final validator. Segmentation, monocular depth and generated meshes are optional additions, not prerequisites. This avoids deploying several vision models before knowing which evidence is missing, but its runtime and user-correction benefit still require measurement.

## Remaining verification

Single-view reconstruction cannot uniquely recover occluded geometry, metric scale or all depth/size combinations without assumptions or added observations. Incorrect templates can make physical validity and image alignment incompatible. No reviewed paper guarantees low correction burden for this app.

A later, separately authorized comparison should freeze the same photos, provider outputs and templates, then compare current repair with source-view fitting. Measure object/relationship recognition, visible alignment, geometry validity, user corrections and latency separately. Check ambiguous and partially occluded desks, not only the one inherited photo. No such comparison was executed for this note.
